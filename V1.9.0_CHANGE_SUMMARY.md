# MOSAIC-Ω v1.9.0 发布摘要

## 产品交互

- 主导航统一为：工作台、任务、结果、智能体、技术透视、设置。
- 模板只负责填充目标、执行要求和交付物；用户确认/编辑后才提交，不再暗中直接启动 Scenario。
- 工作台显示真实阶段、活动 Agent、Concrete Tool、通信、ContextPack、Verifier 与 Evidence；任务页显示权威 Task DAG 和逐任务状态。
- Task Run、Benchmark、Fault Experiment 分离；结果文件严格绑定所选 Run。

## 核心修复

- 修复持久化 Capability Registry 与进程内 Execution Adapter 生命周期不一致导致的连续第二次 Run 失败风险。
- Agent Offline 产生可追溯 `FAULT_INJECTED -> TOPOLOGY_REBUILT -> subsequent TASK_ASSIGNED` 适应链，不把动态重路由伪装成 retry/rollback Recovery。
- 删除重复 ToDAG Web Server/静态前端及重复 legacy experiment result 副本，正式产品只保留一个 Console。

## 技术透视

- Scheduler 展示 `min Σ x_td C_td`、成本分解与硬约束，并显示推荐 Tier 与实际 Tier。
- Agent reliability 展示 Beta posterior `E[p]=α/(α+β)` 与时间衰减。
- Topology 展示边权 `S_ij=0.40D+0.30I+0.20R+0.10L` 与 Laplacian algebraic connectivity `λ₂(L)`。
- Memory 展示 ContextPack ranking、recency、事实召回与 token estimate 边界。
- Low-Entropy Communication 展示 Receiver-aware Δ、hash dedup、decision impact、TTL/budget 与 SEND/MERGE/DEFER/DROP。
- Verifier 展示 predicate、Evidence 与 SHA256 provenance。

## 真实性边界

当前构建环境没有配置公网 Provider credential，且 Python 环境未安装 OR-Tools。因此：

- 不宣称当前 v1.9.0 已完成 fresh public-provider strict run；
- 不把 Greedy/Round-Robin 冒充 OR-Tools；
- 历史 DeepSeek 证据保留在 `evidence/legacy/`，只作为历史 provenance，不作为 v1.9.0 current strict evidence；
- 最终比赛机器仍需配置真实 Provider + OR-Tools 后执行 strict runtime acceptance。

## Windows launcher hotfix

- Removed `PREPARE_OFFLINE_WHEELS.bat`; normal users now have exactly one Windows entrypoint: `START_MOSAIC.bat`.
- Removed the PowerShell launcher chain (`start_mosaic.ps1` / `prepare_offline_wheels.ps1`).
- Added `scripts/windows_launcher.py` as the single setup/lifecycle owner.
- Startup now opens the UI even when optional OR-Tools installation fails; strict scheduler-dependent task start remains fail-closed in the product UI.
- Edge/Chrome app mode is preferred, but browser discovery is no longer a hard startup dependency; the launcher falls back to the system default browser.
- Offline wheelhouse preparation remains available only as an optional advanced command: `py scripts\windows_launcher.py --prepare-offline`.
### Windows zero-install startup hotfix

- Normal `START_MOSAIC.bat` startup no longer creates `.venv`, runs `pip install`, or contacts PyPI.
- The desktop core is loaded directly from local `src/`; GoalSpec validation has a stdlib fallback when `jsonschema` is absent.
- DeepSeek/OpenAI-compatible providers remain usable through the built-in stdlib HTTP transport without the optional OpenAI SDK.
- MQTT and OR-Tools are detected as optional capabilities; missing packages never block the UI from opening. Strict OR-Tools jobs remain fail-closed.
- This removes startup dependence on SSL certificates, proxy configuration, PyPI availability, setuptools build isolation, and network access.
